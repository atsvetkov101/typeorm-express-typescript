## Пример заполнения

## Наименование

Добавить эндпоинт получения списка пользователей с пагинацией

## Описание

### Контекст

`GET /v1/users` возвращает всех пользователей сразу, из-за чего при росте базы ответ становится медленным и тяжёлым.

### Что нужно сделать

1. Добавить query-параметры `page` и `perPage` с валидацией в `src/middleware/validation/users/`.
2. Обновить контроллер `src/controllers/users/list.ts` — использовать `findAndCount` с `skip`/`take`.
3. Вернуть в ответе `total` и `pageCount` вместе с массивом пользователей.

### Затрагиваемые области

- Контроллеры: `src/controllers/users/list.ts`
- Middleware / валидация: `src/middleware/validation/users/`
- Тесты: `src/controllers/users/index.test.ts`

### Ограничения и вне рамок

- Формат ответа остаётся прежним, добавляются только новые поля.
- Сортировка и фильтрация не входят в задачу.

## Критерии готовности

- [ ] `GET /v1/users?page=1&perPage=10` возвращает не более 10 пользователей и поле `total`
- [ ] Невалидные `page`/`perPage` возвращают 422 с сообщением валидации
- [ ] Тесты обновлены и проходят `npm test`
- [ ] `npm run lint` и `npm run tsc` проходят без ошибок
- [ ] Проверено вручную через `curl` с заголовком `Accept-Language: en`
